# 补充排查提示词

脚本已自动覆盖五类常规检查。这份提示词用于**脚本覆盖不到的场景**：深挖某个可疑应用、iPhone 设备、或者用户想自己对着 AI 问一遍。

来源：X 用户 @AIExplorerTim 的公开排查流程（2026-10-27），已按只读原则重写。

## 使用前提

在提示词开头固定声明权限边界，否则模型容易越界：

```
你只有只读权限。不要修改、安装、卸载或停用任何东西。
需要写入的步骤直接跳过并告诉我该怎么做，由我自己操作。
```

## 五步排查

### 第 1 步：找出没印象装过的应用

```
列出这台手机安装的所有应用，包含包名、安装时间、安装来源。
重点标出三类：
1. 桌面没有图标的
2. 安装来源不是官方应用商店的
3. 安装时间和我说得出的安装经历对不上的
按可疑程度排序，每条说明命中的是哪一类。
```

### 第 2 步：谁拿到了高级控制权

> 这一步最关键。监控类软件靠的是驻留能力，不是功能本身。

```
列出拥有下列权限的应用，逐个说明这个权限能干什么：
- 设备管理员
- 无障碍服务
- 通知使用权
- 悬浮窗
对每一个，判断它是常见正当用途（输入法、手表配套、查找设备）还是异常。
拿不准的就说拿不准。
```

### 第 3 步：数据往外发到哪儿

```
列出这台手机当前的对外网络连接，包含应用名、远端 IP、端口。
标出三类异常：
1. 直连 IP 而不是域名的
2. 使用非常规端口的
3. 我不使用该应用时它仍在持续联网的
不要猜测这些地址的归属，只如实列出。
```

### 第 4 步：权限与常驻

```
列出同时满足下面两点的应用：
1. 拥有位置、麦克风、相机中的常驻权限
2. 开机自启或在我没有使用的情况下持续后台运行
逐条说明：这个权限对它宣称的功能是否必需。
```

### 第 5 步：如果真查出了东西

**顺序不能反，删在前面会毁掉证据：**

1. 先把应用详情页、权限页、流量记录全部截图
2. 涉及人身安全的（被跟踪、被定位、被要挟），先断网、保留原机，不要恢复出厂
3. 用另一台设备修改 Google / 手机厂商账号密码，开启两步验证
4. 交给能判断的人看过之后再动手处理

## 深度追问单个应用

怀疑某个具体应用时：

```
针对 <包名> 做一次深度排查：
1. 它的安装来源、首次安装时间、最近更新时间
2. 它申请了哪些权限，实际拿到的是哪些，逐项说明用途
3. 它注册了哪些自启动入口和后台服务
4. 它当前连接了哪些远端地址
5. 它的包名、应用名、图标，和它宣称的功能是否匹配
最后给结论：可疑、正常、或信息不足无法判断。信息不足时必须选第三项。
```

## 不要做的事

| 别做 | 原因 |
|---|---|
| 看到"可疑"就建议卸载 | 用户会丢掉自己要用的软件，或毁掉取证材料 |
| 用"这是间谍软件"这类定性表述 | 只读连接拿不到足以定性的证据 |
| 建议 root 或刷机来彻底清除 | 代价远大于收益，且失去保修 |
| 恢复出厂设置作为首选方案 | 会破坏证据，且用户数据全丢 |
| 建议安装第三方"安全软件"来清理 | 这类应用本身就是广告与权限滥用的重灾区 |
